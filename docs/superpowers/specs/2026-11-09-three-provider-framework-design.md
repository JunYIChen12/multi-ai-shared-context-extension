# 三家统一框架设计（不新增网页连接器）

日期：2026-11-09
需求：`AI-REQ-20261105-001`
基线：`codex/chatgpt-attribution-followup` @ `35cfcb668b535ccf2b9e485d0b12b1f17e50aec1`

## 目标与边界

本工作包补齐 Chrome 扩展已有三家界面的选择边界。ChatGPT 保留现有单标签页临时连接；Grok、Gemini 始终显示“未接入”，不向其网页发送。不宣称三家真实协作可用。

保留现有 `src/core` 的 `ProviderId`、`ProviderAdapter`、编排、来源追踪、Markdown/JSONL 导出格式及 MOCK 隔离。权限仍只有 `activeTab` 与 `scripting`，`host_permissions` 为空。不读 Cookie、令牌、私人会话，不新增依赖、持久后台任务或跨站访问。

当前分支是尚未合并的 ChatGPT 候选分支。框架工作单独从该提交分支，不把本工作包的通过当作 ChatGPT 候选链路的原文准确性或最终验收。

## 方案选择

采用最小界面与状态映射，复用已有 `ProviderAdapter`，不新建一套连接管理器。完整连接器注册/生命周期服务需要多家真实连接经验才能设计，现阶段会把未经验证的网页假设固化进接口。直接实现 Grok/Gemini 连接器则超出本工作包。

实现范围只涉及讨论页选择逻辑及其测试；若为可测试性提取小型纯选择函数，不得扩展成新的连接管理层。无需重写 `extension/discussion.html`、`src/core`、ChatGPT 内容脚本、manifest 或导出器。

## 组件与数据流

1. `src/core` 继续负责统一三家身份、消息状态、编排和导出。`unimplementedAdapter` 是 Grok/Gemini 在正式模式下的唯一适配器；MOCK 仅走用户显式点击的演示入口。
2. `src/extension/discussion.ts` 保留现有连接状态文字；只在 ChatGPT 临时连接后禁用 Grok/Gemini 复选框，并使正式适配器选择限于 ChatGPT。临时标签页参数仅代表“已尝试连接”，不证明页面仍可发送；真实失败继续由现有连接器返回并记录。
3. 已有 `extension/discussion.html` 继续展示三家。未连接状态保留现有“记录未接入尝试”能力。显式 MOCK 按钮独立使用三家演示适配器，不读取正式发送的选择集；结果必须保留 `[MOCK]` 标识。
4. 保持现有“连接后禁用真实第二轮”行为，直到另一个工作包证明至少两家真实连接且完成来源选择的验收。本工作包不改动 ChatGPT 页面脚本、发送及归属判定。

数据路径：用户选择正式发送 → 讨论页选出已接入来源 → 现有编排器调用其适配器 → 统一记录状态/来源/时间 → 现有导出器生成本地文件。未接入来源不能进入正式发送的选择集，不能生成“真实回复”。

## 状态与错误契约

- `已临时连接`：仅表示讨论页有当前 ChatGPT 标签页连接参数，不表示已完成真实网页健康检查。
- `未接入`：Grok/Gemini 固定状态；正式模式不可选、不可发送。
- `MOCK 演示`：只能由显式演示按钮触发，输出不得混入真实会话。
- 连接失效、网页失败、超时等继续使用现有失败/未知结果；不得自动降级为 MOCK 或把空正文记为成功。
- 导入的 JSONL 继续标成未验证导入，不因界面统一而提升信任等级。

## 验收与停止

技术验收采用当前构建在 Chrome 中的可见界面：未连接时三家状态清楚；连接 ChatGPT 后仅它可正式发送，Grok/Gemini 仍为不可选的未接入；点击 MOCK 时三家演示记录仍明确标记；真实第二轮不可启动。补充相关状态/适配器映射的断言测试，并运行 `npm ci`、`npm run check`、差异检查。真实 ChatGPT 回复成功、正文准确及文件落盘属于已有工作包的独立验收，不用本轮离线测试替代。

如果实现统一界面必须扩大浏览器权限、读取登录态、改变现有导出数据契约，或发现当前候选分支的行为与上述假设冲突，停止实现并回到架构评审。新的网页连接器、跨模型真实讨论、持久续聊、发布均为非目标。

## RACI

架构评审（本代理）负责接口边界、方案和技术复审；开发负责实现、自测及证据；用户负责业务验收、合并与发布批准。真实网页登录、2FA 或验证码只由用户操作。设计批准不等于功能验收或发布批准。
