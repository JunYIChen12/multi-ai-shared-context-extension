## 1. 用户意图

把 ChatGPT / Grok / Gemini 接到同一条工作流：同一议题先并行独立回答，再共享观点做交叉讨论或验证。上下文持续积累并落到本地文件。云端协调与本机执行通过 Google Drive 管道交换任务和结果，从而少盯电脑、少手工复制粘贴。用户负责目标和关键决策。

## 2. 已确认的需求与约束

### 2.1 模型与额度

- 接入三家：GPT（ChatGPT 方向）、Grok、Gemini。
- 优先复用已购网页版订阅额度，不默认改成按量 API。
- 把 Codex CLI 当作 GPT 这一路仍是待评估方案。不得承诺 Codex 额度等于 ChatGPT 网页聊天额度。

### 2.2 交互

- 一问多答：各模型先独立作答，再共享观点并交叉讨论或验证。
- 不把目标改回「纯轮流、彼此隔离」。
- 调用可以异步返回。不强制同时打开三个浏览器窗口。

### 2.3 上下文与持久化

- 需要共享上下文、持续积累，并用本地文件持久化。
- 不是多窗口同屏对比，也不是同题广播后各家上下文彼此隔离。
- 历史原文保留。摘要或截断如果采用，必须显式标注并可追溯来源。

### 2.4 产品路径

- 先固定需求，再评估成熟开源或自研。尚未选定某一仓库或某一产品形态。
- 本仓库里的 Chrome 扩展只是候选验证壳，不是用户已经确认的最终选型。

### 2.5 云端与本机

- 本机执行连接用户允许的本地资源。
- 云端侧负责理解目标、拆解任务、审查结果，并在缺项后继续安排。
- 消息通道是 Google Drive `06_AI_Pipeline` 下四个目录：
  - `01_Input_待处理`
  - `02_Processing_处理中`
  - `03_Output_交付结果`
  - `04_Archive_历史归档`
- 目录可以查看，不等于自动队列已经开通。本文件不授权安装监控、出站或自动领取。

### 2.6 少打扰

少长时间盯屏。少手动转发上下文和催进度。完成、卡住或需要用户确认时才通知。

## 4. 范围外

除非另开任务并明确授权，否则不做：

- 对 PLC 或工控目标做写入。
- 模型之间无限循环互聊。
- 默认全盘或越权目录访问。
- 导出 Cookie、私钥，或绕过登录和验证。
- 未经确认的对外发送、删除、付款、推送代码。
- 把本需求文件当成安装插件、改环境、连接 MCP 或建立常驻任务的授权。

后续本地执行要单独写明允许目录、允许操作、次数预算和验收。
