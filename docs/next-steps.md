## 1. 单家已登录网页链路探针

这是合并初始化之后的第一件事。只做一家，建议先选用户当前最好登录、页面结构相对稳定的一家。不要三家一起做。

### 当前阻塞

观察事实：

- 本轮已对 ChatGPT 做两次真实 DOM 路线尝试。第一次失败表现为发送按钮状态竞态；修正后第二次仍返回 `ChatGPT 未在限定时间内开始生成`，尽管网页显示固定回复 `CHATGPT_LIVE_OK`。
- 只读取证中，`[data-message-author-role="assistant"]` 数量为 0；回复祖先链没有 `data-message-author-role`、`data-message-id`、`role="article"` 或稳定 `data-testid`，主要只有生成类名。
- 在提交 `375cce4` 上，`npm run check` 的类型检查、28/28 测试和构建通过。`npm ci` 因系统 npm 缺少 `./cache/policy.js` 失败；这与页面链路失败分开。

判断与决定：

- 已达到既定 DOM 路线停止条件。停止当前 DOM 路线，不再进行第三次选择器或时序猜测，也不扩大权限。
- 恢复开发前必须重新评审以下选项：先证明稳定且隐私安全的锚点；改为用户明确选取/确认回复的半自动路线；或暂停等待稳定公开界面契约。未经重新评审，不继续第 1 步实现。

前置依赖：

- 用户在场完成该网站的登录、2FA 和额度确认。工程检查不能代替这一步。
- 明确允许的操作只包括：打开用户自己的网页会话、填入一条测试问题、读取已经完成的回复文本、把结果写入本地 Markdown 和 JSONL。
- 不导出 Cookie 或令牌，不绕过验证码，不申请 `<all_urls>`。

可自动的部分：类型检查、单元测试、构建、契约测试、导出文件的结构断言。

需要用户在场的部分：登录、2FA、订阅额度、验证码，以及确认页面上那条回复确实来自该网站。

验收：

- 一条真实问题得到一个完成回复，或一条明确失败原因，例如未登录、配额、超时、选择器找不到完成标记。
- 记录里有来源、时间和原文。失败不能显示成成功。
- 本地同时留下 `.md` 和 `.jsonl`，需求编号出现在文件名或正文头部。
- 另一家仍然显示未接入。

停止条件：

- 读完成回复必须导出 Cookie、会话或绕过登录。
- 两次选择器修正仍不能可靠区分「正在生成」和「已经完成」。
- 需要把 Codex 额度当成 ChatGPT 网页额度才能继续。出现这种情况就停下来改方案，而不是悄悄换 API。

## 2. 三家独立回答

前置依赖：第 1 步的一家探针可重复，并且失败原因能区分。

验收：一次问题返回三路结果；每路有来源和时间；任一路失败或超时不阻止其他路。没有真实回复的一路继续显示未接入，不用 MOCK 填坑。

停止条件：为了凑齐三家而放宽到全站权限，或把演示数据写进正式会话。

## 3. 第二轮交叉讨论

前置依赖：第 2 步至少有两路真实完成回复。

验收：用户能选择哪些来源参与注入。注入文本带「来自哪家、哪一轮」。模型看不到未被选中的来源。未完成记录不会被当成观点。轮次有上限。

停止条件：讨论停不下来，或注入内容无法追溯到来源消息。

## 4. 持久化续聊

前置依赖：第 3 步的真实记录能导出。

验收：关闭页面后，只靠 JSONL 恢复同一会话并继续追问。Markdown 仍是给人读的副本。恢复后的旧记录保持未验证导入，直到该条记录能对上一次真实探针。不把 `chrome.storage` 当作本地文件交付。

停止条件：恢复过程需要读取浏览器全部下载目录或网盘。

## 5. 任务预算和 Drive 交接

前置依赖：前面的对话链路可以重复跑通。

验收：同一个任务 ID 不会因为重复扫描执行两遍；超时和重试有上限；通知只包含结论和证据位置。文件在四个约定目录之间的移动仍先用人工或半自动，不在这一阶段安装 MCP、Tailscale 或常驻服务。

停止条件：交接需要未经确认的对外发送、删除或发布。

## 始终不做，除非另开任务

生产设备写入、无限互聊、默认全盘访问、导出登录态、悄悄改用按量 API、把尚未验证的工程壳说成已经可用的产品。
