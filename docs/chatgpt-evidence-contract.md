# ChatGPT 单轮证据契约

这是离线修复用的判定契约。它不证明当前 ChatGPT 页面已经提供这些字段，也不表示真实网页验收通过。

## 归属

发送前只记录结构：轮次 id、角色、顺序、会话地址、生成控件是否可见、错误标记是否可见。不记录旧聊天正文。

本次用户轮次必须是基线里没有的 id，并且只能有一个。它的回复必须是排在这个用户轮次之后、下一个用户轮次之前、同样不在基线里的唯一 assistant id。重挂载保持同一个 id，不能变成新回复。全页数量、最后一个节点、问题文本相同，都不能单独完成归属。

## 终态

正常成功要同时满足：归属成立、该 assistant 内部能读到结束控件、页面生成控件可读且不可见、错误标记可读且不存在、没有观察到停止点击、正文非空并在稳定窗口内保持不变。没见过生成开始也可以成功。

这些条件少任何一个，都不能成功。单独的复制控件、文本稳定或 Stop 消失都不行，三者叠在一起而没有归属或结束控件也不行。

观察到停止控件上的点击后，结果是手停。残留正文不记成完成。没有点击时，不能因为 Stop 消失就猜是手停。

证据不可读、多个候选、信号冲突，或到观察上限仍不充分，结果是未知。可见错误标记是页面错误。这些都不是完成记录。

## 会话地址

只解释两种形状：`https://chatgpt.com/` 是草稿，`https://chatgpt.com/c/<id>` 是会话。其他路径不猜测。

草稿变成 `/c/<id>` 时，只有这份快照里恰好有一个新的用户轮次，才把地址变化看成同一次发送的延续。证明不了就未知。已有会话 id 换成另一个 id，或从会话退回草稿，是隔离，不接收新页面正文。

## 并发和取消

同一标签页的内容脚本只用一把锁。另一个讨论页或同一个 requestId 再进来时直接拒绝，不再点击发送。

外层超时会中止对应采集的信号，内容脚本收到取消后停止轮询并放开锁。已经返回的超时记录不会被晚到正文改写。下一次请求重新取基线，不能把上一轮的节点当成自己的新回复。不会自动重发。

## 仍未核验的 DOM 假设

当前读取器在现有角色属性之外，还依赖这些未对当前页面验收的假设：

- 同一节点上的 `data-message-id` 是稳定身份。缺失则整页轮次不可读。
- assistant 节点内部的复制按钮使用 `aria-label` 为 Copy / 复制 / Copy response，或 `data-testid="copy-turn-action-button"`。找不到则结束控件不可读。
- 可见的 `[role="alert"]` 表示页面错误。这可能漏掉页面自己的错误，也可能把无关提示当成错误。
- 生成状态仍用现有的页面级 Stop 控件，不是每个回复自己的流式标记。
- 地址规则不覆盖语言前缀和其他路径。

这些假设不成立时，结果应是未知或页面错误，而不是成功。真实浏览器兼容仍待后续验证。
